PART A

백업 스키마 v1.0

원칙은 하나입니다 — Raw Events가 유일한 원본. 모든 숙달도·오개념·치료 기록은 이벤트 재생(replay)으로 언제든 다시 계산되므로, 백업이 지켜야 할 것은 원시 이벤트 하나뿐입니다. 이벤트는 삭제·요약·재정렬·재작성 없이 그대로 보존됩니다.

항목내용
스키마 버전1.0 — 파일마다 명시, major 불일치 시 복원 거부
보존 버전 정보config 2.3.0 · masteryModel 2.2.0-ability-beta · curriculum 2.3.0-m1full-pure · graph 2.2.0-m1full35 · schema 1.0
파일 형식무압축(store) ZIP — 외부 라이브러리 0, 바이트 결정성, CRC-32 + SHA-256 이중 무결성
데이터 출처 라벨dataSource: REAL | SYNTHETIC — manifest·README에 강제 표기, 혼합 불가
PART B

생성 파일

완전 백업 ZIP은 지시 명세의 12개 파일을 전부 담습니다:

CHLOE_MATH_BACKUP_YYYY-MM-DD_HH-mm.zip
├── manifest.json            버전·기간·이벤트 수·출처
├── events.jsonl             ★ 원본 — 한 줄 = 한 이벤트, 시간순
├── student-profile.json     표시 이름 정도만 (프라이버시 최소화)
├── versions.json            5종 버전 스냅숏
├── curriculum-reference.json  skillId 해독 사전
├── misconception-reference.json  오개념 id 해독 사전
├── remediation-cases.json   파생 스냅숏 (원본 아님)
├── golden-assessments.json  파생 스냅숏
├── elite-events.json        파생 스냅숏
├── current-derived-state.json  전체 Digital Twin (검증·편의용)
├── integrity.json           SHA-256 체크섬 + replay 검증 결과
└── README.md                복원 방법 안내

통합 아카이브는 full-backup/과 analysis-package/ 두 폴더를 한 파일에 담아(총 29파일) 정기 보관용 원클릭 버튼으로 제공됩니다. 파일명은 CHLOE_MATH_COMPLETE_2026-08-20_17-46.zip 형식입니다.

PART C

Raw Event 무결성

  • integrity.json에 이벤트 수 · 첫/끝 seq · replay 검증 결과 · 파일별 SHA-256 저장
  • ZIP 자체도 엔트리별 CRC-32 — 읽는 순간 손상 감지
  • 가져오기 시 중복 seq · 비단조 seq를 검사해 병합 오염을 원천 거부 (merge는 설계상 금지, REPLACE 복원만)
  • 이벤트 한 글자만 손상돼도: 체크섬 불일치 → 복원 거부 (TEST 3에서 기계 검증)
PART D

Replay 검증 — 백업 성공 조건

Export 직전마다 원시 이벤트를 처음부터 재생해 라이브 상태와 대조합니다. 비교 항목은 이벤트 seq · 스킬 상태(숙달/불확실성/보존) · 오개념 · 치료 케이스 · Elite 프로필 · 학습 큐 · Golden 장부 · 예측 기록 · 전략 흔적 — 하나라도 다르면 BACKUP VALIDATION FAILED로 표시되며 경고 확인 없이는 저장되지 않습니다 (라이브 상태를 일부러 변조한 테스트로 확인).

PART E

복원 테스트

복원은 절대 바로 덮어쓰지 않습니다. 실제 흐름:

백업 선택 → manifest 검증 → 스키마 검증 → 체크섬 검증
→ 이벤트 순서 검증 → 버전 호환 분석 → 샌드박스 재생
→ 결과 비교 화면 (현재 548건 vs 백업 548건 · VALID)
→ 사용자 확인 → 현재 상태 안전 백업(PRE_RESTORE) 자동 다운로드 → 교체

PART F

버전 마이그레이션

  • 같은 ZIP을 복원 입력에 주입 → 샌드박스 검증 화면 "VALID ✓ · 현재 548 vs 백업 548 · 출처 REAL" → 복원 실행 → PRE_RESTORE 자동 백업 → 리로드 후 548 이벤트 무손실 재구성 · 게이트 19/35 보존 · 콘솔 에러 0
  • E2E가 적발한 실결함 1건: 대용량 배열 spread로 인한 스택 초과(브라우저에서만 재현) → 성장형 바이트 버퍼로 재작성, 5MB 스트레스 테스트 추가
PART M

알려진 한계

  • ZIP은 무압축(store) — 파일이 원본보다 작아지지 않음. 수 MB 학습 데이터에서는 무해하나, 수년치 축적 시 압축 도입 검토
  • 복원은 REPLACE 전용 — 두 기기의 로그 병합(merge)은 설계상 금지, 필요 시 별도 마이그레이션 도구로
  • 주간 스냅숏 기반 이력(Elite/M2 추이)은 주 경계 단위 — 더 촘촘한 추이는 raw events에서 직접 재계산 가능
  • 브라우저 다운로드 폴더가 백업의 보관처 — 클라우드 자동 업로드는 미구현 (부모가 파일을 안전한 곳에 복사)
  • 백업 리마인더는 이벤트 100건 기준의 가벼운 안내 — 강제 알림 없음

통합 아카이브 버튼을 누르면 ZIP 파일 하나가 다운로드됩니다. 이 한 파일에 완전 백업과 분석 패키지가 모두 들어 있어요. 한 달에 한 번 정도, 다운로드된 파일을 클라우드나 USB에 복사해 두면 충분합니다.
